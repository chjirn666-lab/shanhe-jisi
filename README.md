# 山河寄思

纪念毛泽东同志的历史阅读与数字纪念网站。采用 HTML + CSS + 原生 JavaScript 与零依赖 Node.js 服务结构，十九个页面均为本项目独立编写，保存在本目录。

## 首页信息结构与功能对应

| 信息区块 | 山河寄思首页 |
| --- | --- |
| 公共导航与深色模式 | 生平足迹、诗词品读、史料索引、问答、我的阅读与寄语 |
| 专题横幅 | 数字纪念长卷专题入口 |
| 关键词搜索与条件筛选 | 搜索历史事件 / 年份 / 足迹地点筛选 |
| 空间示意 + 地点清单 | 时间顺序足迹示意图 + 历史节点清单 |
| 数据概览 | 历史节点、地点、诗词选读和资料来源 |
| 个人记录 | 我的阅读 / 收藏 / 已读进度 |
| 推荐路径 | 主题研读路径 |

`dist/index.html` 是新首页，`dist/long-scroll.html` 保留原数字长卷。首页、独立足迹详情与数字长卷共享历史收藏；寄语仍在长卷中填写和下载。足迹图是时间顺序示意，不是真实地理地图。

## 打开与运行

- 根目录四个 `.cmd` 是 Windows 下的快捷入口，文件名前的 0–3 是为了让它们排在其他文件之前，解压后第一眼就能看到：`0-打开网页.cmd` 直接打开静态首页，不需要 Node；`1-启动网站.cmd` 启动本地服务；`2-启动本地AI.cmd` 启动本地模型（首次运行会联网下载约 1.1 GB 模型，只想浏览网站时不必运行）；`3-停止本地AI.cmd` 停止模型服务。
- 直接双击 `dist/index.html`：可使用首页搜索、地点筛选、足迹详情、主题研读、阅读收藏与进度；从导航进入长卷，可使用诗词切换、本地资料检索、PNG 纪念卡，无需安装依赖。
- 完整本地服务：Node.js 22+，在本目录运行 `npm start`，访问 `http://127.0.0.1:8790`。
- 检查：`npm run check`；测试：`npm test`。
- 浏览器交互检查：先 `npm start`，另开终端设置 `PUPPETEER_MODULE`（puppeteer-core 的 ESM 入口文件绝对路径）和 `BROWSER_PATH`（Chrome / Edge 可执行文件路径），再运行 `node tools/home-check.mjs`、`node tools/library-check.mjs`、`node tools/browser-check.mjs`。截图与结果写入 `preview/`，该目录不纳入版本管理。

## 功能

1. 门户式首页、深色模式与移动端导航；另保留原创水墨 SVG 长卷。
2. 首页将十阶段生平与十二个交互足迹节点合并：通过阶段筛选阅读正文、定位地图节点并查看照片，阶段内容也可在节点详情及本地图文页展开。首页与数字长卷共用资料；阅读手记保存在浏览器。
3. 29首诗词的完整原文、短句节选与创作背景，详情页可阅读全篇并复制带出处的全文，支持设备朗读（需浏览器提供中文语音）。
4. 附来源链接的史料问答。资料库外内容明确说明不足。
5. 自定义寄语和落款、900 × 1200 PNG 纪念卡下载、刷新后恢复。
6. 史料索引与创作说明，所有视觉插画均为本项目 SVG 原创，不是史料照片。

## 足迹中的诗词与语录跳转

足迹正文、章节标题、时间线和生平阶段中出现的已收录作品与名句，均可直接进入对应的诗词或语录条目。同一著作收录多则语录时，会按著作筛选展示，避免只定位到其中一则。正文内链接同样可在本地HTML中使用。

`dist/js/literature-links.js` 统一维护引用识别；修改图文稿件后运行 `node tools/build-footprints.mjs` 会重新生成正文链接。

## 独立AI问答页与足迹详情

- 山河AI现独立为 `dist/ai.html`，首页、足迹详情、长卷及诗词语录馆统一进入此页。问答继续调用本机通义千问1.5B，支持停止回答、资料检索和本地图文跳转。
- 每个足迹均有独立页面，例如 `dist/footprint-1921.html`；首页地图、清单、阶段链接、主题研读和阅读手记均进入对应二级页面。
- 独立页面保留正文、历史照片、时间线、阶段生平、来源、上一站/下一站，并共享首页收藏与已读进度。
- 足迹使用 `ai.html?event=1921` 传入主题；AI页显示当前节点及返回原文入口，未知参数自动回到通用问答。
- AI 研读室提供「从长沙求学到中共一大」和「重庆谈判与《沁园春·雪》」两个固定研读题。模型结合两份本站文字资料归纳时间顺序，页面直接展示本地照片说明。程序附上可展开的资料，使用「同题只看资料」可打开同一批材料。没有模型、返回格式不合格或年份校验未通过时，页面直接展示资料。具体史实可回读资料核对。
- 先启动本地AI，再运行 `node tools/ai-page-check.mjs`，验证独立AI页的真实模型回答和主题关联；`node tools/home-check.mjs` 检查首页入口与导航；`node tools/footprints-check.mjs` 检查12页正文和离线阅读。

## AI 模式

已增加国产轻量本地AI：双击 `2-启动本地AI.cmd`，使用约1.1GB的通义千问1.5B四位量化模型，无需云端密钥。详细启动、停止和离线打包方式见[本地AI使用说明](本地AI使用说明.md)。

默认是**资料检索模式**：按关键词检索本站71条历史、诗词与语录资料，不是大模型推理，也不声称有语义检索能力。

若已有兼容 Chat Completions 的模型服务，将 `.env.example` 复制为 `.env`，填写 `AI_BASE_URL`（包含 `/v1` 等提供方规定的基础路径）、`AI_MODEL` 和 `AI_API_KEY`，重启本地服务。密钥仅在 Node 服务端读取。不要把密钥写进 `dist/`。

`GET /api/status` 返回当前模式；`POST /api/ask` 接收 `{"question":"遵义会议"}`。程序先检索本站资料，再把摘要交给模型，附上的来源由服务器从本地资料表选取。没有相关资料时不调用模型。上游失败时明确回退为检索模式。

云端 Sites 发布的是 `dist/` 静态版，保留完整交互与本地检索；不包含 Node 服务。独立部署包同时包含 Node 后端、Windows 启动脚本、Docker 和 Nginx 模板，详见[部署说明](部署说明.md)。独立版不需要 ChatGPT 登录；启用真实模型时需在后端配置可访问的兼容服务商。AI 输出仍需核对原文。

## 内容与数据边界

- 历史节点为精选阅读，不是完整传记；原文入口包含完整历史背景与评价。
- 本站为生平选读与作品阅读，不对历史人物和历史事件作评价；相关评价以《关于建国以来党的若干历史问题的决议》等官方文献为准，读者可通过史料索引查阅原文。
- 诗词收录29首完整原文，卡片保留短句节选作引子；全文依据人民网、新华网等公开资料逐首核对，异文按通行定本处理，核对来源随篇保存。资料摘要为本项目整理，完整背景仍可通过来源链接阅读。
- 纪念卡和手记只在本地浏览器保存，没有公开留言墙、注册账号或共享数据库。
- 页面没有模拟毛泽东声线、虚构历史影像或虚构用户数量。
- Font Awesome Free 6.4.0 字体和图标沿用其原始许可，保留 CSS 文件头的许可声明。山水与书卷插画为项目原创。
- 相册现有16张本地图片，首页展示12张精选。分为8张人物肖像、5张历史活动、3张足迹场景；每张保存图注、摄影署名、来源和许可。新增青年肖像、新民学会合影、1945年重庆活动与1949年开国大典等记录。现代旧址实景明确注明拍摄年代，荷兰 ANEFO 肖像仍保留年份待核实提示。
- 页面文案未声称已获比赛奖项或已满足传智杯全部规则；参赛材料需按学校正式通知准备。

## 诗词馆与语录馆

- `dist/poetry.html`：29首诗词的完整原文、短句节选、创作背景与阅读提示，支持主题筛选、关键词搜索和收藏；详情页「全篇」区块可阅读全文、查看核对来源并复制带出处的全文。
- `dist/quotes.html`：30则语录节选，标明篇名、时间、语境和来源，支持相同的检索与收藏。
- 两馆均支持带出处复制，剪贴板不可用时提供手动复制框；收藏独立于历史足迹收藏，保存在本机。
- 首页与数字长卷都有入口；长卷和山河问答同步使用扩充后的资料，长卷诗词区可一键跳到对应篇目的全篇。

## 诗词全文的核对与维护

- `poetry-fulltext.json` 是可编辑的源数据，保存29首完整原文、核对说明与核对来源；`tools/build-poetry-fulltext.mjs` 生成前端使用的 `dist/js/poetry-fulltext.js`。
- 原文以人民网理论频道、人民网党史频道、新华网转载、湖北网络广播电视台等公开资料为主，对照百度百科《毛泽东诗词》所录原文逐首核校。不同版本的异文按通行定本处理，例如《七律·和柳亚子先生》取「未能忘」、《七律·登庐山》取「葱茏」；分行只为便于阅读，不改动字句。
- 生成脚本会校验：篇目与 `knowledge.js` 一一对应、原有短句节选逐字出现在全文中、每首都有本站出处与 HTTPS 核对来源。改动全文后运行 `node tools/build-poetry-fulltext.mjs`，再执行 `npm test` 与 `npm run check`。
- 卡片继续用短句节选作引子，完整原文只在详情页与长卷入口提供；不启用 JavaScript 时，仍可通过页面下方的来源链接阅读原文。
- 本次补全的改动清单、原文依据与复测结果见 `诗词全文补全验收.md`。

## 足迹图文档案（本地资料）

- `dist/footprints.html`：十二个节点的完整本地阅读页，含36节原创介绍、48条时间线与16张照片和场景图，正文约7100字。无需跳转外部网站即可阅读这些介绍，关闭网络和 JavaScript 仍可查看正文与图片。
- 新增1918长沙求学与新民学会、1937延安著述、1945重庆谈判、1954杭州制宪、1959重返韶山、1972外交会见六站；全部写入本地稿件和AI检索资料。
- 首页足迹图、右侧清单与独立详情页融入历史照片；长卷同步显示照片和更完整正文，并提供本地详读入口。
- 照片实际拍摄年代在图注中说明；后期人物照不会冒充早期事件现场。
- `biography-periods.json` 保存原十阶段的20段生平正文、来源及对应节点；阶段选择与节点详情共用这份本地内容。
- `footprint-articles.json` 保存可继续编辑的本地稿件；`tools/build-footprints.mjs` 将它生成到图文页和共享资料库。
- 修改稿件后执行 `node tools/build-footprints.mjs`，再运行 `npm run check`。`node tools/footprints-check.mjs` 检查图文联动、手机布局及离线阅读，浏览器环境变量同前述说明。

## 图片维护

`photo-catalog.json` 是图片清单，记录本地路径、来源、署名、许可、对应足迹和文件SHA256。`node tools/download-photos.mjs` 获取清单中缺少的文件；`node tools/build-photo-gallery.mjs` 生成首页精选与分类相册；随后执行 `node tools/build-footprints.mjs` 同步图文页面。

`node tools/photo-check.mjs` 检查分类筛选、搜索排序、图片深链接、署名和离线浏览。所有图片已随独立包提供，日常打开网站不需重新下载。CC BY-SA 4.0 的场景照片在各使用位置保留摄影者和许可说明。

## 边界问题回归

- 多标签页分别修改寄语和收藏时，只合并本次动作改变的字段，避免覆盖另一页刚保存的内容。
- 收藏或已读记录格式损坏时可恢复写入，同时保留另一份有效记录；浏览器禁止存储时仍会提示无法保存。
- 从引用链接打开诗词或语录后，关闭阅读窗口会保留条目所在分页，并将键盘焦点返回对应卡片。
- 浏览器环境配置同上，运行 `node tools/edge-check.mjs` 验证以上问题及AI停止、断线回退。
